# Media content and calendar contract

TreePane loads MediaContent only while media mode is active. Ordinary mode has no media provider, grid, thumbnail cache or timeline instance, and no media filtering or calendar geometry bindings. Leaving media mode destroys that subtree and cancels its outstanding work. Retiring the Files view on blade close also cancels its provider; reopening reads the current location. Teardown does not reconcile selection against a cleared media model. Inactive providers ignore root, capability, filter-scope and backend-readiness changes until activated.

Media uses cached backend `children-window` pages of 400 entries, one request at a time. Scope starts at the current folder. Recursion is explicit and skips directory symlinks. Listing stops with a visible partial-scope notice at 100,000 entries or 4,096 descendant directories; backend caps are also exposed. Media recognition includes MIME and suffix fallbacks. Recognition is separate from decoder support: unsupported or corrupt images and videos stay visible. Comprehensive decoding and explicit playback belong to tasks 6.2 and 6.3 and are not complete here.

The existing selection controller receives the media model and exact paths. Query and metadata filters remove hidden action targets. Query, recursion and size are per view; the ordinary query and location/history remain intact. A supplied location descriptor requires explicit capabilities; the existing local provider path is retained while the Locations integration is pending. No arbitrary URI becomes a POSIX path.

`MediaDates.normalize(value, precision)` accepts provider dates, including `{value, precision}`, epoch seconds/milliseconds, calendar years/months/days, and ISO timestamps with offsets. The existing local provider supplies cached local mtime strings. An explicit offset is converted into the local calendar. Date-only values are not interpreted as UTC. Precision can reduce the known calendar fields; it never invents fields absent from the input. Invalid or explicitly unknown records are Undated. Calendar arithmetic uses day ordinals, independent of daylight-saving day length. An optional numeric timezone offset is available for deterministic tests; the UI omits it and uses local time.

`MediaDates.localeRule(Qt.locale().name, Qt.locale().firstDayOfWeek)` uses Qt's resolved locale and first weekday. Qt's QML locale interface does not expose minimum days in the first week; the territory minimum-days table is the Gregorian `weekData/minDays` subset from Unicode CLDR release 48. Default territory 001 uses one day, and the listed territories use four. First weekday and minimum days are independent: Portugal and Iceland are examples of Sunday-start/four-day rules. Week-year follows those same two inputs. A system change takes effect when the runtime's locale is refreshed or restarted.

Source: https://github.com/unicode-org/cldr/blob/release-48/common/supplemental/supplementalData.xml#L4676-L4696. The retained Unicode-3.0 license is [CLDR-LICENSE](CLDR-LICENSE). No new runtime dependency or network request is needed.

`MediaBins.records` normalizes once per input change. `build(records, level, parent, rule)` returns bins with half-open day bounds and exact source indices. All marks at a level share the returned maximum count. The builder retains empty calendar periods; the view omits zero-count bins by default before compaction. “Show empty timeline periods” under Media is off by default and persists per Files view. It changes the rail, never the media records or query. Single-item periods use adjacent 26-unit selectable rows when they fit the rail; periods with several items retain count bars. The viewport outline appears only when occupied tile rows exceed the grid viewport, calculated from the record count, columns, row pitch and final tile height rather than estimated GridView content height. Limited precision goes into a counted unknown-precision child when membership in finer bins cannot be established. Undated is the final overview bin. Child weeks and days are clipped to parent bounds. Histories over ten years initially coarsen to years; fine week/day bins require a month/week parent. `ordered` gives the main view a stable chronological model, with unknown day precision at the end of its month, unknown month precision at the end of its year, and Undated last. It retains original order for equal dates and never merges files into private variant stacks. An explicit PaneView sort instead applies the existing TreeOrder comparator to all matching rows across pages, including name, size, dates and secondary sorts. Stable exact-path ties keep page arrival order from deciding equal sort values. The backend continues to enumerate stable name pages; changing the sort does not re-enumerate media. The selected path and current first visible tile are independently retained through reordering.

`MediaTimeline` chooses months when all marks fit at least 18 scaled pixels per target; otherwise it uses years. Year-only records also start at years so they never imply a month. Extremely long spans aggregate adjacent years into counted ranges, which drill through smaller ranges to individual years. Every level shares one maximum count. A child is unavailable if it cannot fit readable targets in the available height. Changing scope or query resets detail; ordinary media scrolling does not.

Bin geometry comes from the actual grid columns, row pitch and tile height. A bin stores the exact contiguous row intervals containing its ordered indices; adjacent periods sharing a tile row both intersect that row. For name/size or descending date order, separated intervals remain separated: scrolling through a gap never lights a period whose items are elsewhere. Binary search finds visible intervals and seek positions without scanning all files on each scroll. The axis stays chronological even when the content has an explicit non-date order; its outline is the calendar extent of visible content, not a second linear scrollbar. The viewport projects its first and last partial bin intersections onto one square outline, including intervening calendar gaps only when the view option shows them. Counts are independent of selection. No file metadata is read during scrolling. Blue roles are centralized on MediaTimeline: lightBlue #89b4fa and darkBlue derived at 2.25 darkness; the later shared design-token gate must account for these explicit semantic colors.

The header names the current period and detail. Down enters the last explicitly navigated period, otherwise the first visible period; Up returns to its parent. Timeline-focused Left/Right are coarser/finer; Up/Down and Home/End seek nonempty periods. The buttons expose accessible names and support Space/Return. Browser modified arrows and Escape retain their existing handlers. Pointer presses on a count interval seek immediately; dragging the sole outline retains the grab offset. When enabled, empty intervals are inert. Seek cancels existing flick momentum and assigns contentY without selecting files, changing the query, filtering the model, animation, flashing or hover decorations. The legacy ImageGrid/TimelineScrubber used by Goblins is unchanged.

## Decoder capability matrix

The thumbnail child handles PNG/JPEG/WebP through the existing Rust image decoder. Compatible RGB/gray ICC profiles up to 1 MiB are retained through scaling with the profiled image's colour type; incompatible profile/pixel spaces fail visibly. Unprofiled images keep their existing encoding path. The cache namespace advances for profile retention. `media_colour.py ROOT --binary RUNTIME` generates a real RGB profile with the installed lcms2 library and verifies exact profile retention for PNG/JPEG/WebP; this is not a complete display-colour or HDR tone-mapping qualification.

Other admitted formats use the installed `ffprobe` and `ffmpeg`; no tool is downloaded or installed. Both commands receive bounded bytes through stdin, with only the `pipe` protocol and fixed demuxer/codec allowlists. Image pipes receive their exact byte length as `frame_size`; PAM's `P7` signature supplies the demuxer hint absent from a nameless pipe. Decode limits remain 16 MiB input, 16384 pixels per edge, 64 million source pixels, 512 MiB address space, four seconds per FFmpeg command within the eight-second thumbnail deadline, one codec/filter thread, zero regular-file writes in FFmpeg, and at most 8 MiB PNG output. Oversized or unsupported media stays visible with a failed preview. Cache identity includes source metadata and requested dimensions; stale caller stamps cannot retain a replaced file's thumbnail.

## Application icon resolver

`FileIcons.resolveApplication(entry, override, desktopEntry, iconPath)` returns `{icon, icon_source, glyph}` for the existing wheel adapter and application rows. Explicit glyph/theme/bundled-mark overrides take precedence, followed by the matching desktop entry's Icon, the existing trusted backend source or bundled tool mark, and the fallback glyph. Theme names go through the supplied `Quickshell.iconPath`; absolute paths are accepted only from the trusted desktop catalogue. `entry.icon_source` retains the existing backend-validated local-source contract, never a remote row URL. The bundled herdr, tmux and pane marks keep their existing assets.

SafeApplicationIcon accepts optional `desktopId`, `applicationDescriptor` and `applicationOverride`. Only a nonempty desktop id evaluates the desktop catalogue; legacy iconName/trustedIconSource callers keep their original resolution branch. MenuButton forwards optional appDesktopId, and the Open with repeater supplies desktop_id. Properties keeps its generic Open action glyph. Each decode dimension clamps to 128 device pixels. Descriptor consumers retry candidates after an image error, remember at most four failed sources until descriptor inputs change, and display the resolved override/descriptor glyph when assets are exhausted. The resolver itself remains pure.

The renderer regression is `tests/vm/fixtures/media_icons.py`; its canonical expectations are E-39-01 through E-39-06. On candidate c3abf5d, instrumented ordinary close/open cycles create no new renderer instances and perform no catalogue or application-resolution calls; opening Open with activates those paths. This is a warm-open observation, not a claim that shell startup constructs no hidden menu icons.

Run `tests/vm/expectations/39-application-icons.sh` with `OVM`, `OVM_HOME` and `OVM_SSH_PORT` pointing to the prepared harness. This is application resolution, not completion of personal folder overrides, semantic/agent identity or every launcher context-index collision.
